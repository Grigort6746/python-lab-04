# Лабораторная работа 4. Алгоритмический мини-пакет

Пакет `razbeg` содержит:

- итеративный и рекурсивный алгоритмы Евклида для НОД;
- сортировки вставками и слиянием;
- стек;
- пять генераторов входных данных с seed;
- программу замеров и результаты в CSV.

Основные размеры замеров: **100 000, 1 000 000 и 10 000 000**.
Для объяснения роста времени вставок добавлены отдельные контрольные замеры
на 256, 512 и 2048 элементах. Они не заменяют основные размеры.

## Установка

Нужен Python 3.11 или новее. Открыть PowerShell в папке `lab_04`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Для работы пакета нужна только стандартная библиотека; pytest и ruff нужны для проверок.

## Условия и ошибки

Сортировки принимают `list[int]`, включая пустой список. Возвращают отдельный новый
список, исходный не меняют. Дубликаты и отрицательные числа допустимы.
Другой тип контейнера или нецелый элемент вызывает `TypeError`.
`bool`, строки и числа с плавающей точкой не принимаются.
В реализациях сортировок нет `sorted` и `list.sort`.

Оба варианта НОД принимают целые неотрицательные числа, хотя бы одно больше нуля.
Неверный тип, включая `bool`, вызывает `TypeError`, отрицательные числа и пара `(0, 0)` —
`ValueError`. Для крайне больших чисел рекурсивный вариант может дать `RecursionError`.
Текущий предел можно посмотреть через `sys.getrecursionlimit()`; часто он равен 1000,
но зависит от окружения. Пакет этот предел не изменяет.

Стек работает по LIFO: последним добавлен — первым извлечён.
`push` добавляет, `pop` извлекает, `peek` смотрит вершину без удаления.
`pop` и `peek` пустого стека вызывают `EmptyStackError`, подкласс `IndexError`.
`len` показывает число элементов, `bool` — наличие хотя бы одного.

## Генераторы

`make_data(kind, size, seed=42)` возвращает список целых чисел.

| kind | Содержимое |
| --- | --- |
| `random` | Случайные числа от `-size` до `size` включительно |
| `sorted` | Числа от 0 до `size - 1` по возрастанию |
| `reverse` | Те же числа по убыванию |
| `nearly` | Возрастающий список с `max(1, size // 100)` обменами соседних элементов при `size > 1` |
| `duplicates` | Случайные числа из 16 значений: от -8 до 7 |

Для воспроизводимости используется отдельный `random.Random(seed)`.
Одинаковые аргументы дают одинаковый набор в одном окружении.
`sorted` и `reverse` от seed не зависят. Для случайных наборов разные seed обычно
дают разные данные, но математической гарантии различия любого маленького набора нет.
Глобальное состояние генератора случайных чисел не меняется.
Неверный тип размера или seed вызывает `TypeError`, отрицательный размер
или неизвестный kind — `ValueError`.

## Сложность

В таблице N — число элементов, S — размер стека, K — число делений Евклида.

| Алгоритм/операция | Время | Дополнительная память |
| --- | --- | --- |
| НОД с циклом | O(log min(a,b)) делений для положительных a,b | O(1) переменных |
| НОД с рекурсией | Столько же делений | O(K) кадров вызова |
| Вставки, лучший случай | O(N) | O(N), включая копию результата |
| Вставки, средний/худший случай | O(N²) | O(N), включая копию результата |
| Слияние, лучший случай с пропуском готовых блоков | O(N) | O(N) |
| Слияние, средний/худший случай | O(N log N) | O(N) |
| `push` стека | Амортизированно O(1) | O(S) всего у стека |
| `pop`, `peek`, `len`, `bool` стека | O(1) | O(1) на операцию |

Для НОД с одним нулевым аргументом число шагов постоянно. Оценка по делениям
не учитывает увеличение стоимости арифметики при росте длины больших целых чисел.
Все генераторы требуют O(N) времени и памяти, если считать операции Random постоянными.

## Benchmark

Основной запуск:

```powershell
.\.venv\Scripts\python.exe -m razbeg.benchmark --output results/main
```

По умолчанию выбраны все пять типов входа, размеры 100 000, 1 000 000, 10 000 000,
seed 42 и пять повторов. Создаются:

- `runs.csv` — длительность каждого выполненного запуска и отметки пропусков;
- `summary.csv` — медиана, минимум и максимум по каждому случаю;
- `environment.json` — параметры запуска, версия Python и сведения о системе.

Генерация данных, подготовка независимой копии, создание эталона и проверка результата
происходят вне таймера. Внутреннее копирование, необходимое самой сортировке для её
контракта «возвращать новый список», входит во время вызова.
Встроенный `sorted` используется только для эталона вне реализации сортировок.

Вставки на `random`, `reverse`, `duplicates` при размере свыше 4096 пропускаются
с явным `status=skipped`: на целевых размерах число сдвигов становится чрезмерным.
Пустое время в такой строке означает отсутствие замера, а не нулевую длительность.
На `sorted` и нашем `nearly` вставки измеряются на всех трёх основных размерах.
Слияние измеряется на всех пяти типах и всех трёх размерах.

При необходимости ограничение можно изменить через `--quadratic-limit` или снять
флагом `--force-quadratic`. Последний разрешает в том числе запуск на 10 миллионах
элементов с квадратичным числом действий; завершение такого запуска может быть
практически недостижимо в рамках лабораторной.

Контрольный запуск для квадратичного роста:

```powershell
.\.venv\Scripts\python.exe -m razbeg.benchmark --sizes 256 512 2048 --kinds random reverse --output results/control
```

Фактические результаты и их разбор — в `BENCHMARK.md`.
Обычные тесты не запускают большой benchmark автоматически.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\ruff.exe check .
.\.venv\Scripts\python.exe -m razbeg.benchmark --help
```

Если окружение активировано, можно использовать `python -m pytest` и `ruff check .`.
